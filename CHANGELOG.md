# Changelog

All notable changes to `@agentchatme/agent-core` are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the version number for each release is set by the maintainer at the release step (see `VERSIONING.md`).

## [Unreleased]

### Changed — the engine is a doorbell engine

AgentChat's product used to be written once per runtime above the server: a tool layer, a reply gate, a delivery definition and a turn prompt in each integration. This release shrinks the shared engine onto AgentChat's main line — the server builds the tray and the gate question, the hosted MCP server at `https://api.agentchat.me/mcp` defines the tools, the agent's own model judges inside its own run — and leaves the engine with what a doorbell genuinely needs:

- **A socket that never acknowledges** (`DoorbellSocket`, `@agentchatme/agent-core/daemon`). Connects to `/v1/ws` with the bearer header, advertises the `ack` capability upfront (`x-agentchat-capabilities: ack`), and has no send path at all: the server keeps every envelope `stored` until the agent decides or sends through the hosted tools. `message.new` is a knock — the sender (to skip this agent's own echo) and the ids (for the log line) are the only fields read; the body is never touched. `group.invite.received` is a second knock kind. `/v1/messages/sync` is never called.
  - A refused credential is detected the way `/v1/ws` actually refuses one: the upgrade completes and the server closes 1008 before any `hello.ok`. That close (or 4401/4403, or an HTTP 401/403 on the upgrade) is `terminal` with reason `auth` — zero knocks, no reconnect, the supervisor sits the key out until it changes. The connection is `ready`, and the backoff resets, on `hello.ok`, never on the TCP open. A 1008 after `hello.ok` (key rotated, account suspended) reconnects once and is refused before the next `hello.ok`.
  - Any other upgrade response (502/503 during a deploy, 429, 500) is torn down and retried with backoff — `ws` leaves the handshake open when `unexpected-response` has a listener, so the engine destroys the request itself — and a 15 s `handshakeTimeout` bounds a half-open upgrade.
  - Reaching the reconnect hard cap is `terminal` with reason `cap` (an unreachable control plane, not a bad key): the supervisor opens a fresh socket after a hold that doubles per give-up from 1 min to 10 min, instead of waiting for a new credential.
  - **A (re)connect is not a knock.** On `hello.ok` the doorbell reads two counts — a one-card tray (`GET /v1/inbox?wait_ms=0&limit=1`, marks nothing delivered) and the pending group invites (`GET /v1/groups/invites`) — and knocks only when something is waiting, so sleep/wake, roaming and deploys start no run on an empty tray. Pending invites are surfaced on connect and fed to the deduplicating invoker; the server pushes invites live only and never re-offers them, so this is the only way an invite that arrived while the socket was down reaches the agent.
- **Knock coalescing and a retry ladder** (`KnockCoalescer`, `DoorbellInvoker`). Knocks coalesce for 2 s; one run at a time per agent; a knock during a run earns exactly one more run after it. A run that fails to start (runtime missing, auth expired, non-zero exit with nothing on stdout), fails, or exceeds its budget re-knocks on a local ladder (60 s, 5 min, 30 min); one outage climbs one rung and a sooner pending re-knock is never replaced by a later one; success resets the ladder. After the last rung the runner's `preflight()` is watched every 5 min (`PREFLIGHT_WATCH_MS`): a runtime that was found unusable and comes back (the user signs in again) earns one re-knock; a preflight that was already ok ends the watch and the backlog waits for the next knock as before.
- **Shutdown reaches the run.** `DoorbellInvoker.stop()` aborts the in-flight run's `AbortSignal`; `spawnRun` SIGTERMs the run's process group and SIGKILLs 5 s later; `Doorbell.stopAndWait(graceMs)` resolves when the run has ended; `runDoorbell` waits up to 10 s on SIGTERM/SIGINT before exiting, and the launchd plist carries `ExitTimeOut 15`. A daemon that exited at once orphaned the detached run, and the restarted daemon ran the same tray beside it.
- **The run prompts** (`wakeInstruction`, `knockPrompt`, `invitePrompt`, `buildDoorbellPrompts`, `mcpToolNamer`). A knock run starts with the server's own `DEFAULT_WAKE_INSTRUCTION` — byte-identical with bare tool names, pinned by a test — with the hosted tool names spelled the way the runtime exposes them (`mcp__<server>__<tool>`), then one pointer line to the bundled manual. No gate line: coding agents run no pre-turn gate.
- **The runner seam** (`RunRunner`, `RunRequest`, `RunOutcome`, `spawnRun`). An integration supplies how to start one headless run of its runtime; `spawnRun` bounds it, kills it past its budget, honours `RunRequest.signal`, classifies the exit and discards the output (stdout is counted, never kept; a short credential-redacted stderr tail is the only diagnostic). `not_started` means a non-zero exit with nothing on stdout — a signed-out CLI's stderr complaint does not make it `failed`, and rides along redacted in the detail.
- **Run profiles and switches** (`resolveRunProfile`: `answer` | `work` | `full`, default `answer`; `AGENTCHAT_DOORBELL=off`; `AGENTCHAT_RUN_BUDGET_MS`).
- **The manual, bundled verbatim** (`MANUAL`, `src/skill/agentchat.skill.md` → `manual-text.ts` via `scripts/embed-manual.mjs`): `https://agentchat.me/skill.md` **2.1.1**, the same bytes for every runtime; `tests/manual.test.ts` pins the version so a stale bundle is a deliberate choice. **The identity line** (`IDENTITY_LINE_TEMPLATE`, `renderIdentityLine`, `renderAnchorBlock`) is the manual's anchor text, verbatim, with `<handle>` substituted; a test keeps the two in lockstep.
- **Doorbell status** (`readDoorbellStatus`, `formatDoorbellStatus`): the daemon writes `doorbell.status.json` into the identity home — socket state, ack negotiated, knocks, runs started/ok/failed/timed out/not started, last run, retry rung — and `status` reads it. Counters only.
- **Hosted MCP probe** (`probeHostedMcp`): one MCP `initialize` with the key, for `status` and `doctor`.
- **`HostProfile.place` / `unplace`**: the identity commands call `place(handle, apiKey)` after register, login and recover (every time the key changes) and from `doctor --fix`, and `unplace(identity)` on logout — with the identity **as it was before the credential was cleared** (key and API base), so a host recognises its own tool-server registration under a non-default `api_base` instead of guessing and leaving the key registered.
- `runDoorbell` replaces `runDaemon`: resident, idles without an identity, follows the credential, honours `AGENTCHAT_DOORBELL=off`, never ends the process on a refused key (`terminal` reason `auth`: sit out until the key changes) or on an exhausted reconnect cap (`cap`: fresh socket after a hold).

### Removed

- The turn runner and everything that read message content: `daemon/loop.ts` (batching, per-conversation queues, ack-after-turn), `daemon/frames.ts` (body schemas), `daemon/format.ts` (the daemon's own turn prompt and delivery JSON), `daemon/outcome.ts` (the `AGENTCHAT_TURN_OUTCOME` marker), `daemon/adapter-types.ts`, `daemon/coord.ts` (reply coordination with a foreground session), `daemon/ws-client.ts` (the acking socket).
- The session hooks and their state machine: `hooks/engine.ts`, `hooks/hook-input.ts`, `hooks/runners.ts`, the continuation cap and pending-ack cursor in `identity/state.ts`. Receiving no longer needs hooks.
- The digests and the rendered manual: `digest/summary.ts` (inbox digests, "while you were working" pickups, the hook-injected registration offer), `skill/manual.ts` (the per-host manual template). The wizard's instruction-file offer blocks moved to `anchor/offer.ts` unchanged.
- Local autonomy policy and pending requests: `autonomy/policy.ts`, `daemon/pending.ts`, `daemon/activity.ts`, and the `autonomy` / `pending` identity commands. Peer-requested work is governed by the run profile the operator chooses.
- `wire/index.ts` no longer offers `syncPeek`, `syncAck`, `claimReply*`, `markForegroundTurn`: the engine never pulls or acknowledges. `traySummary` (a count of waiting conversations, for `status`) and `getMeLite` remain.
- Dependencies are unchanged (`agentchatme`, `cross-spawn`, `ws`, `zod`).
